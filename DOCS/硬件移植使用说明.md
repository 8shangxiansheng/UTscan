# 硬件移植使用说明

> 适用范围：UTscan v2.8.4 备份仓库（`Backup\UTscan-v2.8.4-core-20260829`）
> 目的：将系统从现有三硬件平台（Spectrum M3i.3242 + JSR DPR500 + 众为兴 ZMC）移植到其他硬件平台时，明确步骤、环境准备、配置项与注意事项。
> 关联文档：[硬件SDK接口功能清单](硬件SDK接口功能清单.md)、[HARDWARE-CONFIG](HARDWARE-CONFIG.md)、[软件使用说明书](软件使用说明书-20260829.md)

---

## 1. 移植总览

### 1.1 当前平台约束（事实，代码锚点）

| 约束 | 锚点 | 说明 |
|---|---|---|
| x86 进程硬绑定 | `UTscan.csproj` L14 `<PlatformTarget>x86</PlatformTarget>` | 全部 5 个厂商 DLL 为 32 位 |
| RID=win-x86 | `publish-self-contained.cmd` L25 `set RUNTIME=win-x86` | WoW64 跑在 x64 主机 |
| P/Invoke 封装层 | `Hardware/Daq/SpectrumNative.cs`、`Zmc/ZmcNative.cs`、`PulseGen/JsrNative.cs` | 三设备寄存器/函数直调 |
| 接口抽象 | `Core/Interfaces/` 三接口（IDataAcquisition / IMotionController / IPulseGenerator） | 上层不感知具体硬件 |

### 1.2 移植分级（按工作量）

| 级别 | 场景 | 工作量 | 说明 |
|---|---|---|---|
| L0 | 同型号换机/换卡 | 极小 | 驱动重装 + hardware.json 微调 |
| L1 | 同品牌同系列升级（如 M3i 换更高端型号） | 小 | Native 层寄存器兼容性核对 |
| L2 | 同品牌换系列（如 M3i→其他 Spectrum 卡） | 中 | 寄存器集差异适配 |
| L3 | 换厂商换品牌（如 DPR500→其他脉冲器、ZMC→其他运动控制） | 大 | 重写对应 Native + 驱动适配 + UI 类型检查点同步 |

## 2. 移植步骤（以换运动控制器为例，L3 完整流程）

### 步骤 1：环境准备

1. **SDK 获取**：从新厂商获取 x86（32 位）原生 DLL + 头文件 + 示例；
   - 若厂商仅提供 64 位 DLL → 需先决策：改 x64 平台（涉及全部 5 个 DLL 与 csproj RID）或驱动桥接；
2. **驱动安装**：目标机安装新硬件驱动（OS 级）；
3. **文档收集**：厂商 API 手册（函数签名/返回值语义/线程约束）；
4. **验证环境**：厂商自带示例程序在目标机跑通。

### 步骤 2：实现接口

新建 `Hardware/<NewVendor>/<NewDevice>Controller.cs`，实现对应接口：

- 换运动控制器 → 实现 `IMotionController`（12 个方法 + 2 事件，见 `Core/Interfaces/IMotionController.cs`）；
- 换采集卡 → 实现 `IDataAcquisition`（Initialize/Start/Stop/WaitForNewFrame/GetCurrentData…）；
- 换脉冲器 → 实现 `IPulseGenerator`（ApplyParams/EnableOutput/Readback…）。

参考现有实现模式：
- `Hardware/Zmc/ZmcMotionController.cs`（运动：连接→使能→绝对移动→位置读取→急停回滚）
- `Hardware/Daq/SpectrumDaqCard.cs`（采集：Open→寄存器配置→DMA 分配→WAITDMA 线程→帧发布）
- `Hardware/PulseGen/Dpr500Controller.cs`（脉冲：串口/SDK 通信→参数下发→发射启停）

### 步骤 3：P/Invoke 封装

新建 `Hardware/<NewVendor>/<NewDevice>Native.cs`：

- `[DllImport(...)]` 惰性加载；`CallingConvention` 按厂商约定（StdCall/Cdecl）；
- 所有返回码检查；超时/重试策略；线程模型与调用线程一致性。

### 步骤 4：装配替换

`Program.cs` 装配段（约 L61-73）将具体类替换为新实现：

```csharp
motion = new UTscan.Hardware.Zmc.ZmcMotionController();   // ← 替换为 new NewVendor.NewController()
```

### 步骤 5：UI 类型检查点同步（关键遗漏点）

以下 `is` 类型检查在替换后必须同步修改，否则运行期功能静默失效：

| 位置 | 检查 | 依赖的新实现需提供 |
|---|---|---|
| `MainForm.cs` L976 | `_motion is ZmcMotionController` | `LastConnectError` 诊断属性 |
| `MainForm.cs` L1023/L1039 | `_daq is SpectrumDaqCard` | `Capabilities` / `LastConnectError` |
| `AscanForm.cs` L910/L934 | `_daq is SpectrumDaqCard` | `GetKpis()`（FIFO 丢帧 KPI） |
| `MainForm.cs` L617/L1092/L1099/L1115/L1128 | `_pulse is Dpr500Controller` | `ConnectionKind` / `IsConnected` / `LastConnectError` |

> 建议：替换实现时在新类补齐同名诊断属性（LastConnectError / Capabilities / GetKpis），可避免改 UI。

### 步骤 6：配置

更新 `src/UTscan/hardware.json`（模板）与新平台匹配，见第 4 节配置项。

### 步骤 7：构建与测试

```bash
dotnet build src/UTscan/UTscan.csproj -c Release    # 编译
dotnet test tests/UTscan.Tests/UTscan.Tests.csproj  # 327 用例基线
scripts/publish-self-contained.cmd 2.8.4            # 打包
```

### 步骤 8：Mock 对照验证

`useMock:true` 跑通 Mock 模式（接口契约自测）→ 再切真机，逐设备探测→连接→联调。

## 4. 配置项说明（hardware.json）

```json
{
  "ipAddress": "192.168.0.11",      // ZMC 运动控制器 IP
  "port": 502,                      // ZMC TCP 端口
  "serialPort": "COM1",             // DPR500 串口
  "baudRate": 4800,                 // 波特率（DPR500 固定 4800/8N1）
  "timeoutMs": 8000,                // 连接超时（<5000 被钳位到 5000）
  "sampleRate": 100000000,          // 采集采样率 Hz（<9e6 回退 100MHz，M3i 下限）
  "sampleCount": 1024,              // 采样点数
  "useMock": false,                 // true=Mock 仿真
  "enableMotionController": false,  // true=启用运动控制（当前调试阶段禁用）
  "triggerIo": -1,                  // ZMC 触发输出 IO（-1=未配置；扫查需 ≥0）
  "triggerPulseWidthMs": 5          // 触发脉冲高电平宽度 ms
}
```

详细字段说明见 [HARDWARE-CONFIG](HARDWARE-CONFIG.md) 与 [运动控制配置说明](运动控制配置说明.md)。

## 5. 注意事项与风险

### 5.1 架构级

1. **x86 决策**：换平台时先定架构，避免中途改 RID（影响全部 DLL + 发布脚本）；
2. **UI 类型检查耦合**：`is SpectrumDaqCard` 等 10 处——新实现需提供同名诊断属性；
3. **寄存器语义**：M3i 的 SPC_/M2CMD 寄存器语义与采样率下限（9MHz）是新厂商适配难点；
4. **DMA/线程模型**：Spectrum 的 WAITDMA 通知机制是采集线程核心，换卡后需重写帧同步。

### 5.2 工程级

5. **fail-closed 安全**：真机模式连接失败拒绝启动，不自动回退 Mock（Program.cs L131）——移植时保持该策略；
6. **急停回滚**：连接序列中运动失败触发 `EmergencyStopAsync` 回滚（MainForm L1243）——新控制器必须实现；
7. **保留 IO 校验**：ScanService 校验 TriggerIo 不占用伺服使能口——新平台接线时核对；
8. **厂商二进制许可**：仓库内厂商 DLL 仅保证开箱可构建，正式分发前核对许可条款。

### 5.3 现场级

9. ZMC 类网络控制器：静态 IP 同网段 + 防火墙放行 + 网口灯确认（历史 20008 教训）；
10. 触发链路接线：TRIG/SYNC → DAQ TRIG 口（非 X0/X1 多功能口），换平台后重新核对；
11. 采样率/点数/长度联动：`8 对齐` 与 `POSTTRIGGER < SEGMENTSIZE` 是 Spectrum 不变式，新采集卡须核对自身约束。
