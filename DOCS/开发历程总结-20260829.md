# 超声显微扫查系统（UTscan）开发历程总结

> 生成日期：2026-08-29
> 范围：基于 Agent 开发该系统的全部对话会话整理
> 当前版本：v2.8.4

---

## 一、项目背景与目标

### 1.1 项目背景

本系统是**超声显微扫查系统上位机软件**（UTscan），用于驱动三台工业设备完成超声 C 扫成像检测：

| 设备 | 型号 | 作用 |
|---|---|---|
| 数据采集卡 | Spectrum M3i.3242-exp | 高速 ADC 采集回波信号（12-bit，最高 500MS/s） |
| 脉冲收发仪 | JSR DPR500 | 高压脉冲激励探头 + 接收回波放大 |
| 运动控制器 | ZMC 系列 | 驱动 XY 运动台按规划路径扫描 |

技术栈：C# / .NET 8 / WinForms，x86 架构（全部原生 DLL 为 32 位），自包含发布（green portable）。

### 1.2 核心目标

1. 打通 DPR500 → 探头 → 试件 → 回波 → M3i 采集 → 软件显示的完整信号链；
2. 实现 A 扫实时显示、C 扫成像、B 扫截面、FFT 频谱等分析功能；
3. 支持扫查参数配置、数据导出（CSV/ADTX）、程序内更新；
4. 真机现场可用 + 无硬件可 Mock 仿真双模式。

## 二、各阶段开发任务与关键决策

### 阶段 0：项目基线（v1.8.8 之前）

- 已有代码从旧项目（DyZMC）迁移而来，含 FFT/小波/中值滤波等信号处理库。
- 遗留问题：PInvoke 硬编码、串口参数假反馈、无更新机制、明文凭据等。

### 阶段 1：硬件连接修复（v2.0.0，Phase 1 六项）

**任务**：修复三硬件连接与触发链路。

**关键修复**：
- **[P0] 连接对话框全字段回传**：超时/触发 IO/脉宽可编辑并回写 `ConnectionConfig`（原对话框仅回传 IP/Port，其余修改丢失）。
- **[P0] 触发链路在线自检**：链路诊断复刻生产链路（DPR 武装 → ZMC 单边沿 → Spectrum X0 帧计数推进）。
- **[P1] hardware.json 超时 3000→8000ms**（生效值 `Math.Max(config,5000)`）。
- **[P1] DPR 重连竞争保护**：10 秒冷却门 + fire-and-forget 清理。
- **[P2] 关断确认轮询加宽**：5×100ms → 10×100ms（共 1s），保持 fail-safe false。

**关键决策**：真机/仿真双装配（`useMock`），DLL 缺失降级仿真；fail-closed 配置加载（真机程序拒绝启动不自动回退 Mock）。

### 阶段 2：三硬件现场联调（v2.0.1 ~ v2.0.6）

**任务**：现场首次联调，解决三设备实际问题。

**问题与解决**：

| 问题 | 根因 | 解决 |
|---|---|---|
| DAQ SEGMENTSIZE 报错 | 1020 点非 8 倍数 | `AlignSegmentSize` 对齐 8 倍数（v2.0.1） |
| DAQ START "posttrigger exceeds segment size" | 触发窗口不变式破坏 | PRETRIGGER+POSTTRIGGER=SEGMENTSIZE 且 PRETRIGGER>0（P3-FIX2） |
| DPR 0x83F 句柄枚举失败 | 硬编码请求 4 句柄 > 库中 1 台 → SDK 整次拒绝 | `JSR_GetAsciiInfo` 读 elementCount 按量分配（P3-FIX3c/3d，四层：仪器/通道/Pulser/Receiver） |
| ZMC 20008 TCP 未建立 | 环境问题 | 排查清单交付现场（ping/IP/防火墙/网口灯） |

**里程碑**：三硬件首次现场连接（备份 v2.0.6 源码快照）。

### 阶段 3：数据管线加固（v2.1.x）

**任务**：解决高 PRF 采集路径的分配压力与并发正确性。

**关键决策与实现**：
- **AscanFramePool 缓冲池**：`ArrayPool<float>` + `AScanData` 对象池，消除每帧堆分配。
- **所有权契约**：池化帧仅内部持有，外部经 `GetCurrentData()` 克隆；`_frameLock` 串行化发布/克隆。
- **PointCount 解耦**：池化数组可能超长，用逻辑采样点数 `PointCount` 与 `Samples.Length` 解耦（修复尾部虚假零值）。

**引入并修复的回归**：
- v2.1.1 `Array.Resize` 裁剪池化数组 → 归还时 "buffer is not associated with this pool" → v2.1.2 改 PointCount 解耦方案。

### 阶段 4：7 维度系统审查与修复（v2.2.x）

**任务**：全面审查功能完整性/逻辑正确性/IO/边界/一致性/兼容性/测试。

**高优先级修复**：
- L1 扫描启动异常路径 `_isScanning` 锁死 → `ownsScan` 标志 + finally 兜底；
- L3 ResetAsync 后 `NeedsReinitialize` 失效 → 并入 `_state==Closed` 判定；
- L2 扫查后 DPR 触发模式未恢复 Internal。

**中优先级**：ConnectionForm 补 TriggerIo 回写、加载设置警示、链路诊断挂菜单、更新回滚 /xo 失效、ADTX 导入矩阵填充。

**低优先级批量（v2.2.1）**：防御性修复（空句柄/阈值≤0/FFT 镜像 bin/采样率空洞）+ 状态同步（DPR 发射状态/游标/延迟） + 舍入与显示 + 配置兼容。

### 阶段 5：A 扫功能增强（v2.3.x）

**任务**：按优先级实施 A 扫交互增强。

- 多帧叠加对比、测量游标与峰值捕获、多帧平均显示、异常自动检测、显示滤波模式、历史帧回放、触发参数可视化（v2.3.0）。
- 闸门/回读/脉宽/阈值/状态栏问题修复（v2.3.1）。
- 采样长动态显示、闸门超窗警示、DAQ 重启刷新（v2.3.2/2.3.3）。

### 阶段 6：扫查断点续扫（v2.4.0）

**任务**：手动/异常停止后从中断点恢复。

**关键决策**：列粒度断点（每点记录行列），停止时 `SaveBreakpoint`，续扫 `ResumeFromBreakpointAsync` 跳过已扫行列；数据不重复（跳过已完成点位）不丢失（ScanForm 累积保留）。

### 阶段 7：时间轴物理正确性（v2.5.0）

**任务**：修复 A 扫时间轴两个 P0 级缺陷。

- **P0-1**：波形 x 映射丢失 startUs（`startUs+i*dt` 抵消）→ 改 `i*dt` 绝对时刻，抽 `SampleToPixelX` 纯函数；
- **P0-2**：PRETRIGGER 时间原点未计入 → `AScanData.TriggerOffsetUs` 字段，采集侧填 `pre×dt`，全链换算统一减偏移（深度误差从 0.94~14.7mm 修正）；
- P1-3/P2-5/P2-6：DelayUs 语义澄清、TimeOfFlightUs 命名、两"延迟"区分。

### 阶段 8：审查报告修复 + 采样配置持久化（v2.5.1 ~ v2.7.2）

- H-A/1.5 A 扫无数据诊断、H-C DataReady 先克隆、H-B FifoGate 警示、3.2 PRF×点数乘积上限、H-D 发射联动采集就绪（v2.5.1）。
- FFT 链路修复（PointCount 防御 + Hann 窗）（v2.6.1）。
- 采样点数硬编码回退统一 `DefaultSampleCount` 常量（v2.7.1）。
- hardware.json 采样参数回写（v2.7.2，最小化 JsonDocument 更新）。

### 阶段 9：SPC_TRIG_DELAY 触发后延时（v2.7.0）

**任务**：实现"跳过始波直接采底波"。

依据 M3i 手册 p.85：`SPC_TRIG_DELAY` 位于触发链最末级，仅平移触发事件，不影响 pre/post 比例。DAQ 面板加「触发延迟(µs)」。

### 阶段 10：停止后无法重启采集（v2.7.3 ~ v2.8.3）

**问题**：停止采集后再点开始无响应。

**排查路径**：
- v2.7.3 A+C 方案（自动重初始化 + 线程引用清理）→ 未根治；
- v2.8.2 加诊断 `DescribeState()` + 启停埋点；
- **v2.8.3 根因实锤（现场日志）**：`state=Running` 但 9ms 后 `running=false` 且无日志——`StopAsync` 后 DMA 残留 ABORT，`CARD_START` 未重建 → WAITDMA 立即 ERR_ABORT → 线程启动即退。**修复：启动前先幂等 STOP 清残留 + ABORT 分支 stopReq==false 时重试**。

### 阶段 11：TCG 深度补偿（v2.8.0）

**任务**：随深度自动提升增益（参照 EPOCH 650 DAC/TCG），厚件定量。

**关键决策**：软件 TCG（非硬件）——DPR500 单增益寄存器无法帧内分段，故在 `ComputeImagingValue` 前按绝对声程乘 `10^(dB/20)` 因子；O(1) 预计算查表；曲线编辑器独立窗体。

### 阶段 12：界面控件补充与缺陷修复（v2.8.1 ~ v2.8.4）

- 采样点数直接配置入口（与采样长度双向联动）、A 扫全屏按钮、深度补偿主菜单入口（v2.8.1）；
- TCG 按钮灰色缺陷修复（v2.8.4）。

## 三、超声扫查知识详解（结合本系统）

### 3.1 A 扫（A-scan）

单点回波波形：横轴=时间（µs），纵轴=幅值（V）。本系统 A 扫显示链路：

```
M3i ADC(12-bit) → raw(±32768) → 电压 = raw×量程/32768/1000 (V)
→ 池化帧 → _frameLock 内发布 → 外部克隆 → 100ms 定时器轮询显示
```

**时间轴换算**：`time_us = index×dt − TriggerOffsetUs`，其中 `dt=1e6/采样率`，`TriggerOffsetUs` 为 PRETRIGGER 触发前偏移（v2.5.0 修复）。触发时刻为 t=0。

### 3.2 B 扫（B-scan）

沿某扫描线的**截面图**：横轴=位置，纵轴=深度。本系统每列 = 一个位置点的完整 A 扫，`depth_mm = (t−zeroOffset)×velocity/2000`（往返÷2）。

### 3.3 C 扫（C-scan）

**平面投影图**：每个像素 = 空间位置 (X,Y) + 闸门内特征值。本系统 `_matrix[iy,ix]` 由 `ComputeImagingValue` 逐点填充。

### 3.4 闸门（Gate）

时域矩形窗口（`StartUs + WidthUs`），框定特征提取区间。9 种成像模式决定提取特征：幅值类（峰值/峰峰/正负峰）、声程类（TOF/阈值穿越）、相位/均值。

### 3.5 关键参数概念

| 参数 | 说明 | 本系统实现 |
|---|---|---|
| 采样率 | ADC 采样频率，决定时间分辨率 | 100MHz 默认，ClampSampleRate 9~500MS/s |
| 采样点数/长度 | 点数=长度×采样率/1e6，8 对齐 | `_numSampleCount` ↔ `_numSampleLengthUs` 双向联动 |
| PRF | 脉冲重复频率，DPR500 发射速率 | 内部/外部触发，DMA 带宽校验 |
| 增益 | 接收器放大（-13~66dB） | A 扫增益条实时联动 |
| PRETRIGGER | 触发前预采集样本 | 触发前偏移，最小 32 样本 |
| TRIG_DELAY | 触发后延时，跳过始波 | v2.7.0 实现 |
| TCG/DAC | 深度补偿增益曲线 | v2.8.0 实现 |
| -6dB 定量 | 半功率点缺陷尺寸测量 | 包络搜索，乘声速/2000 |

### 3.6 采样定理

奈奎斯特：采样率 ≥ 2×探头频率。本系统默认 100MS/s 支持 ≤50MHz 探头；1MHz 探头时每周期 100 点，波形精细。过低采样率导致混叠，过高导致数据量大（有 DMA 带宽上限校验）。

## 五、最终成果与遗留事项

### 5.1 最终成果

- **稳定版本**：v2.8.4，测试基线 327/327；
- **完整功能**：A/B/C 扫、FFT、闸门分析、TCG、-6dB 定量、断点续扫、历史回放、深度轴、多帧叠加、异常检测、程序内更新、Mock 仿真；
- **健壮性**：DMA 重建、并发加固、时间轴物理正确、配置持久化。

### 5.2 遗留事项

1. **ZMC 20008**：现场网络环境问题，排查清单已交付但待现场执行；
2. **TCG 真机校准**：补偿曲线效果需参考块实测验证（软件实现已就绪）；
3. **-6dB 定量真机验证**：包络半功率搜索需真实波形确认；
4. **双通道 UI 选择器**：数据层支持双通道但 UI 仅显示第一通道（结构性增强待排期）；
5. **hardware.json 全量回写**：目前仅采样参数回写，IP/触发 IO 等仍靠手工编辑；
6. **DataReady 无订阅者**：事件契约（先克隆后回调）已实现，但当前无实际订阅路径。
